# Phase 5 — Evaluation and verification reliability

Phase 5 adds reproducible quality checks around document retrieval and evidence claims.
The evaluation data is small and synthetic, with provisional labels. It is useful for
regression checks; it does not establish general AI or real-world factual accuracy.

## What the scores mean

Retrieval answers “did the search return the passage we labelled relevant?” **Recall@K**
is the fraction of relevant passages found in the first K results. If a question has two
relevant passages and the first five results contain one, Recall@5 is 1/2. **Precision@K**
is the number of relevant passages in the first K divided by K. **MRR** is the average
reciprocal rank of the first relevant result:
a result at rank 1 scores 1, rank 2 scores 1/2, and a miss scores 0. **nDCG@K** rewards
relevant passages near the top and normalizes against the best possible order.

No-answer queries do not enter those relevance averages because they have no relevant
passage. Their empty-result rate is reported separately. Missing/deleted labels and
unknown retrieved IDs are counted and excluded from relevance scoring. Precision is zero
when an answerable query returns nothing. Median latency is always reported when measured;
p95 is shown only with at least 20 samples. The benchmark does not claim statistical
significance.

Verification answers “did this procedure classify a claim against the supplied passages
as labelled?” **Precision** is the fraction of predicted class items that were labelled
with that class. **Recall** is the fraction of labelled class items found. **F1** balances
precision and recall; macro F1 gives each class equal weight. A **confusion matrix** shows
which labels were mistaken for which other labels. False-support rate is false SUPPORTED
predictions divided by all expected non-SUPPORTED cases. Abstention means an eligible,
checkable claim was returned as INSUFFICIENT_EVIDENCE.

An incomplete claim must not receive support: “In addition, it has” does not identify a
complete proposition, even if a passage contains those same words. Eligibility checks
retain the original wording and explain the exclusion. Leading pronouns such as “it” are
held as INSUFFICIENT_CONTEXT; this implementation does not invent an antecedent or
reconstruct the sentence.

A citation can point to a real passage and still fail to support the associated statement.
Conversely, a passage match does not establish that the source is accurate or reliable.
SUPPORTED describes the bounded evidence procedure, not factual truth.

## Run on this Mac

Start local PostgreSQL and Qdrant, then run the ordinary checks:

```bash
docker compose --profile infrastructure up -d --wait postgres qdrant
bash scripts/check.sh
backend/.venv/bin/python scripts/test_database.py
```

The database runner creates and removes a uniquely named scratch PostgreSQL database
and Qdrant collection. It does not reset development records. To run the cached local
embedding benchmark, first confirm the pinned model is already cached; the test never
downloads it automatically:

```bash
RF_RUN_LOCAL_EVALUATION=1 backend/.venv/bin/python scripts/test_database.py -k phase5_retrieval_benchmark
```

The runner indexes the 16 passages in `evaluation/datasets/retrieval-v1.json` through
the actual parser, local embedding model, PostgreSQL and Qdrant; then it runs the same 20
queries through semantic, BM25 and hybrid retrieval. The writer and verifier are not
called in this retrieval experiment. The dataset is intentionally synthetic and its
labels are provisional. No held-out tuning split or human review has occurred.

The recorded run had 17 answerable queries and three no-answer queries. On answerable
queries, Recall@1/3/5/10 was 0.794/0.941/1.000/1.000 for semantic, 0.735/0.882/0.882/1.000
for BM25, and 0.853/0.941/1.000/1.000 for hybrid. MRR was 0.897, 0.847, and 0.924;
nDCG@3 was 0.898, 0.834, and 0.919 respectively. BM25 median latency was 2.76 ms,
compared with 18.20 ms semantic and 18.67 ms hybrid. Two fresh scratch-index runs
produced identical passage rankings and metric scores after deterministic tie-breaking.
All three methods returned at least
one result for every no-answer query, so the empty-result rate was 0%; this retrieval
endpoint has no calibrated answerability threshold. The tiny dataset does not establish
that semantic or hybrid search is superior. The 16 indexed text uploads took about 3.15
seconds end-to-end (upload, parse, embed, and index combined); those stages were not timed
separately. Memory was not measured.

The offline verification benchmark and eligibility metrics are generated by:

```bash
backend/.venv/bin/python -m pytest -c backend/pyproject.toml backend/tests/test_verification.py -k 'phase5'
```

This uses the deterministic mock verifier only. It does not contact a hosted model. For
live APIs, no evaluation is configured or enabled by these commands.

## Read the saved results

Inspect `evaluation/results/phase-5-retrieval.json`,
`evaluation/results/phase-5-eligibility.json`, and
`evaluation/results/phase-5-verification.json`. Results include the dataset version,
configuration, raw per-query predictions or latencies, aggregate scores and limitations.
`evaluation/phase-3-results.json` remains the original six-record retrieval pilot, while
`evaluation/phase-4-results.json` remains the original 12-case controlled regression
baseline. Neither baseline should be presented as a generalization benchmark.

## What remains unverified

The claim language gate is a conservative deterministic heuristic, English-only, and can
misclassify uncommon grammar. It deliberately abstains on leading pronouns and does not
perform safe context reconstruction. Exact-sentence and narrow numeric/negation mock
rules do not provide semantic entailment. No NLI model, hosted verifier, live provider,
source reliability check, or human-reviewed benchmark was run. The retrieval corpus is
too small to compare broad semantic quality or support statistical conclusions. Long-
document chunking alternatives, component-level parse/embed timing, peak memory, and
production-scale behavior remain unmeasured. Review annotation provenance in
`evaluation/annotations/verification-guidelines.md` before expanding the dataset.
